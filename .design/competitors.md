# Competitive watchlist

The formal baseline is [`research/ecosystem/competitive-analysis.md`](../research/ecosystem/competitive-analysis.md). This file tracks changing product signals and hypotheses that may warrant refreshed research.

## Categories to watch

- Generators and updaters: Cookiecutter, Copier, Yeoman, Hygen, Plop, framework starters.
- Native project tools: Cargo, Go, uv, Poetry, Hatch, npm create, Maven, Spring Initializr.
- Developer control planes: Backstage software templates, internal developer portals, repository policy platforms.
- Provider CLIs: GitHub, Docker, Vercel, Railway, Fly, Cloudflare, Supabase, Firebase, AWS, Azure.
- Release/dependency automation: Changesets, release-please, semantic-release, GoReleaser, Renovate, Dependabot.
- Repository assistants and coding agents: watch plan transparency, permissions, evidence, and migration behavior rather than generation demos.

## Evaluation lens

For each material change, record date/source and assess:

- Does it address creation, maintenance, or both?
- Is repository intent explicit and portable?
- Can changes be previewed, explained, reversed, and applied non-interactively?
- How are local edits and upgrades reconciled?
- What code executes, with which permissions and credentials?
- Are machine outputs/versioned schemas stable?
- Does it preserve native ecosystem conventions?
- What remains unowned after generation?

## Current differentiating hypothesis

Aruo’s durable position is the connection between repository intent, evidence, safe transitions, and long-term standards evolution. If another project solves that better, Aruo should integrate, narrow, or reconsider—not manufacture differentiation.
