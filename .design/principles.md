# Working principles

These are product heuristics under active refinement. Accepted engineering principles live in [the design principles guide](../docs/design-principles/README.md).

1. **Begin with the repository’s intent.** Do not infer a universal goal from language or framework alone.
2. **Show the plan before the effect.** Consequential work should be inspectable before execution.
3. **Make provenance useful, not possessive.** Record enough to upgrade safely without claiming ownership of user files.
4. **Prefer one coherent path.** Add options only when they represent distinct supported needs.
5. **Use native tools visibly.** Users should understand which underlying command and version produced evidence.
6. **Treat findings as teaching moments.** State expected outcome, observed evidence, risk, rationale, and remediation.
7. **Make the safe path the fast path.** Security and reversibility should not require expert-only flags.
8. **Keep local workflows complete.** Hosted features add collaboration, not basic capability.
9. **Earn automation gradually.** Read, explain, plan, apply, verify, then consider autonomy.
10. **Design deletion and retirement.** Every capability, template, plugin, cache, and service needs an exit path.
11. **Preserve uncertainty.** Distinguish fact, policy, inference, recommendation, and future intent.
12. **Optimize for maintainers after year five.** Repeated exceptions, noisy checks, stale choices, and clever abstractions compound.
