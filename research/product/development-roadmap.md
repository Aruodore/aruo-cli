# Development roadmap

Roadmap versions are capability gates, not dates. A milestone ships only with docs, migration notes, telemetry-free local evidence, security review, and upgrade path.

## 0.1 — prove the model

- domain model, config/schema, workspace discovery, human/JSON reporting;
- deterministic inspect/check/plan for one Go library and one Python package;
- create/adopt with foundation policy and provenance lock;
- transactional filesystem changes, dry run, golden fixtures;
- documented architecture and conformance corpus.

Why: validates lifecycle abstractions against two meaningfully different ecosystems before broad catalog work.

## 0.5 — useful daily driver

- Go, Python, Rust, TypeScript library and CLI blueprints;
- React/Vue and Node service profiles;
- `add`, `fix`, first semantic merges, upgrade conflict UI;
- task runner, GitHub adapter, docs/release capabilities;
- signed first-party artifact catalog and cross-platform releases.

Exit: maintainers can create or adopt real projects and complete at least one safe standard upgrade.

## 1.0 — dependable contract

- stable CLI/config/plan/finding schemas and compatibility policy;
- complete offline behavior, plugin process protocol and SDK;
- release prepare/verify/publish separation, SBOM/provenance integration;
- Windows/macOS/Linux qualification, accessibility and performance budgets;
- security audit, threat model, recovery testing, public governance.

## 2.0 — repository lifecycle platform

- organization policy packs and multi-repository inventory;
- migration campaigns, dependency/API compatibility analysis;
- health trends and evidence export; optional hosted collaboration;
- mature ML/CV and benchmark profiles;
- IDE/LSP integration backed by the same local engine.

## 5.0 vision

- federated repository knowledge graph and architecture assistance;
- evidence-grounded documentation/test/migration proposals;
- policy simulation across fleets before rollout;
- onboarding paths personalized to verified repository facts;
- portable ecosystem standards and community-governed artifact network.

AI features arrive only after deterministic facts/plans/evidence exist. Hosted fleet features arrive only after the single-repository experience earns trust.
