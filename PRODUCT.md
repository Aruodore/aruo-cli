# Product

## Register

product

## Users

Developers and AI coding agents starting applications that may become real businesses or operational systems. They need a repository whose intent, boundaries, failure behavior, and unresolved production responsibilities are understandable before product-specific code exists.

## Product Purpose

Aruo creates domain-neutral application foundations with trustworthy defaults. Each supported framework has a comprehensive template and a lean template. The comprehensive template supplies broadly reusable production infrastructure without inventing business entities. The lean template supplies the smallest production-safe core and makes every omitted concern visible. Success means a generated repository starts cleanly, explains why each capability exists, fails clearly, passes one meaningful quality gate, and never claims that scaffolding alone makes an application production-ready.

## Brand Personality

Intentional, candid, dependable. The product should create confidence through explicit contracts and working evidence, not through impressive-looking feature lists.

## Anti-references

- Generic SaaS dashboards, fake analytics, billing screens, task trackers, workspaces, and other invented product domains.
- Boilerplates that install many integrations without exercising or explaining them.
- Decorative landing pages presented as evidence of application architecture.
- “Production-ready” claims based on file presence, badges, or happy-path builds.
- Clever abstraction layers that hide native framework behavior.

## Design Principles

1. Practice what the starter teaches: every generated contract must be enforced by code or classified as unresolved.
2. Keep product decisions out of infrastructure: provide capabilities and seams, not fictional business models.
3. Make failure legible: loading, empty, invalid, unavailable, unauthorized, and unexpected states are first-class.
4. Prefer framework-native conventions and boring infrastructure over cross-framework cosmetic uniformity.
5. Evidence outranks claims: generated projects must qualify through their real ecosystem commands.

## Accessibility & Inclusion

Generated interfaces target WCAG 2.2 AA, semantic HTML, keyboard operation, visible focus, reduced-motion support, sufficient contrast, and screen-reader-readable status and error communication. Accessibility checks belong in qualification; color or motion must never be the only carrier of meaning.
